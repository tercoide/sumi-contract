# sumi-contract

The paperwork part of the **sumi suite** (GambasCAD for 2D plans, sumi-e for 3D and rendering, sumi-designer for the BIM model). It gathers the tasks needed to build a design, makes the budget, splits it among speciality contractors, and tracks progress and payments. Written in **Gambas 3** (runtime 3.19+, tested with 3.22). Comments may be in English or Spanish, as in the rest of the suite.

Started 2026-11-17 as a fresh skeleton modeled on sumi-designer (not a fork: none of the CAD/OpenGL code came along). Pieces copied from sumi-designer: `AppLog`, `Icons`, `fSettings` (with its `Config.Behaviour()` pattern), the `actions` svg icon set and the program icon. sumi-designer's notes call the suite's quantities and costs program **sumi-sheets**; this is that program, now named sumi-contract.

The user writes the work to do in task lists (`starting.txt`: 0 project data, 1 budget from sumi-designer's quantities, 2 Gantt, 3 unit price analysis of each task, 4 contracts with their work and payment progress). The lists are the bare minimum: add what a real work's paperwork needs. Reference material (`starting.txt`, `answers.txt`, `questions-next-stages.txt`, `licita2003.xls` and its VBA as .txt) stays in the folder but out of the repository (`.gitignore`). Work is committed on `main` (the only branch; the user chose one branch on 2026-11-17).

## The web version (`web/`, started 2026-11-17)
Decided with the user 2026-11-17: sumi-contract must run on Windows too, so it becomes a web program (no WSL); sumi-designer may follow with wgpu. The Gambas version stays as the reference until the web one matches it. Hosting will likely be Google Cloud under the company's Google Workspace (Cloud Run + PostgreSQL, Google sign-in); develop locally until then. Every dependency must be permissive (MIT, Apache, BSD): the user may sell the suite later.
- **TypeScript on Node 22** (Ubuntu's Node has no built-in TypeScript: `tsc` compiles `src/` and `test/` into `dist/`). In `web/`: `npm start` builds and serves on http://localhost:8064 (data in `web/data/`, `SUMI_DATA` and `SUMI_PORT` to change); `npm run dev` adds Vite's live reload on :5173; `npm test` checks the Spanish, the types and the model; `npm run gui-test` (after a build) drives the screens in Playwright's Chromium (`GUI_SHOTS=<dir>` saves screenshots, `GUI_LANG=en`).
- **`src/model/`** is the port of the Gambas model, file by file: `prices.ts` (PriceBook, Resource, Machine, LaborCharge, Analysis), `budget.ts`, `schedule.ts`, `contracts.ts`, `company.ts`, `project.ts`, `change.ts`, `cmd.ts` (Cmd.module). Plain objects, the JSON of each is the Gambas file's (a `.contract-proj` opens unchanged, change log included); dates are `yyyy-mm-dd` strings counted in UTC (`dates.ts`).
- **`cmd.ts`**: `run(session, command, args)`; a `Session` is {project, company, who, group} (no globals: a server has many people). Same commands, texts, log, undo and redo as the Gambas version, plus `project.get` and `change.get` (the Gambas screens read the objects; the web ones and the AI ask). A command that fails after touching something puts it back. Snapshots compare with null = "" (Gambas writes an empty text as null).
- **`src/server/`**: `main.ts` (plain `node:http`: `/api/projects`, `/api/projects/import`, `/api/projects/<id>/file`, `/api/projects/<id>/report/<kind>`, `/api/run`, `/api/me`, and the built screens), `auth.ts` (Google sign-in) and `store.ts` (the company's files and one `.contract-proj` per project in the data folder, written at once after each change; PostgreSQL when it goes to a server). The person is the one signed in with Google, or `SUMI_USER` / the computer's user when there are no keys; `data/people.json` gives each (by address, or by name) a permanent user id.
- **Google sign-in (`auth.ts`, 2026-11-18):** OpenID Connect code flow with PKCE, no library; the ID token comes straight from Google's token endpoint over TLS, so its signature isn't checked (OIDC Core 3.1.3.7), but iss, aud, exp, nonce, email_verified are. Keys: Google's downloaded OAuth client JSON as `data/google-keys.json` (or `SUMI_GOOGLE_KEYS`, or `GOOGLE_CLIENT_ID` + `GOOGLE_CLIENT_SECRET`); redirect URI `<url>/auth/callback`. Who may come in: `data/login.json` `{url, domains, allowed}` or `SUMI_URL`, `SUMI_DOMAINS`, `SUMI_ALLOWED`; a domain is checked against the token's `hd` (Workspace), not the address. The server refuses to start with keys and nobody allowed, and refuses a `SUMI_HOST` other than localhost without keys. Sessions: an HttpOnly SameSite=Lax cookie, 30 days; `data/sessions.json` keeps its sha256. With logins on, `/api` answers 401 without a session (the screens show the sign-in page) and refuses POSTs from another origin. `test/auth.test.ts` runs the flow against a fake Google (`SUMI_GOOGLE_AUTH_URL`, `SUMI_GOOGLE_TOKEN_URL` point the server at one). Roles are still to come.
- **PDF reports (`model/pdf.ts`, `model/reports.ts`):** the port of PdfDoc and Reports (same layout and texts, so the Gambas Spanish is used); numbers and dates in the request's language (`text.ts` `locale()`). `makeReport(project, company, kind, contract, cert)` -> `{pdf, name, pages}` or `{error}`. The `report.pdf` command (a server extra) makes it to check and returns `{url}`; the screens open the url in a new tab with `&lang=` (the top bar's PDF menu, the certificate's PDF button). The test reads them with `pdfinfo`/`pdftotext` when installed; `SMOKE_PDF_DIR=<dir>` keeps them.
- **`client/`** (React + Vite, built into `dist/client`): `App.tsx` (projects list; a project with the top bar and tabs, address `#/p/<id>/<tab>`), `work.ts` (`useCommand` reads again after every change, as the Gambas tabs' `Reload`), `fields.tsx` (fields that run a command when left or on Enter; numbers typed the person's way, "1.234,5" in Spanish), `tabs/` (all six: Project, Budget, Gantt, Pricing with `pricing/`, Contracts with `ContractorsPanel`, History).
- **Spanish:** texts are `tr("...")` on both sides. `npm run i18n` (also in build and test) collects them, takes the Spanish from `../.lang/es.po` (the Gambas one) or `web/i18n/es.po` (the web's own), writes `src/i18n/es.json` and lists what has none; add those to `scripts/fill-es.py`, run `python3 -I scripts/fill-es.py` and `npm run i18n` until it says 0. Values shown with `tr(value)` go in the script's `RUNTIME` list. The server answers in the language the screens send (`x-sumi-lang`).
- **`test/model.test.ts`**: the smoke test's checks with the same numbers, and a file written by the Gambas version (`test/gambas/`, made with `SMOKE_KEEP_DIR=$PWD/web/test/gambas gbx3 . -- --smoke-test`).
- **Names:** the root `.gitignore` drops anything called `core` or `core.*` (Gambas core dumps): no folder or file with that name in `web/`.
- **Screenshots:** the snap Firefox can't read `/tmp` profiles and shoots before the data arrives; use the GUI test's `GUI_SHOTS`.
- **The licita2003 library** (the user's own, free to ship) is in `web/library/licita2003` and `web/library/added`; `prices.import` takes it by name (`{library: "licita2003"}`, read by the server) or uploaded files (`{files: {name: text}}`); `model/library.ts` is LibraryImport working on texts.
- **Commands only the web has:** `project.get`, `change.get`, `book.get`, `resource.list {full}`, `schedule.suggest` (every duration as one change).
- **AI assistant (`src/server/assistant.ts`, `client/src/Assistant.tsx`, 2026-11-18):** the Gambas Assistant's loop with the official SDK (`@anthropic-ai/sdk`, Apache-2.0): `client.beta.messages.stream` + `finalMessage()`, `claude-opus-5-5`, adaptive thinking, effort set explicitly (default high), `fallbacks: "default"` with the `server-side-fallback-2026-07-01` beta, top-level `cache_control`, the `sumi` tool (with `eager_input_streaming`: its input is checked before running) and `web_search_20260209` (AR). Our own loop, not the tool runner: a turn is one command group (`beginGroup`; the session's who becomes the AI with its model), can be stopped (AbortSignal; also when the page closes), and drops itself from the conversation when it fails (its changes stay, undoable). `pause_turn` is sent again; `refusal` and `max_tokens` don't run that reply's tool calls. One `Chat` per person and project in the server's memory. Routes `/api/assistant` (GET state, POST streams NDJSON events text/step/round/done), `/stop`, `/new`. Settings `data/ai.json` {model, effort, webSearch, apiKey} or `SUMI_AI_*`, `ANTHROPIC_API_KEY`. Tests: `test/assistant.test.ts` with a canned `Sender`; the GUI test sets `SUMI_AI_CANNED=<json array of replies>`.
- **Chromium's `scrollIntoView` returns a promise:** an effect written `useEffect(() => el.scrollIntoView())` hands React a promise as its cleanup and blanks the page; use braces.
- **Still to port:** the design link (sumi-designer); roles for the logins.

## Decisions (with the user, 2026-11-17, `answers.txt`)
- **Team and AI:** a company's employees, later with logins and roles (one person may have several); BIM style, one place for the data (a server later). Until then the person is `Config.UserName`. The AI works for its person (the company has Claude Enterprise) and should help with everything, from searching prices on the web to applying them. Changes are applied and logged (undo available), not proposed.
- **Change log:** who, when, how (person / AI with model / import), what, before and after; kept forever in the file for now (maybe versions on a server later). sumi-communications (a separate program) is still open: proposed that each program keeps its own log and communications connects people.
- **Prices:** each project has its own (no shared company library). Labor and equipment are calculated, but a typed price can override (licita2003's hand edits). Prices must be updated constantly (inflation): update coefficient, imports, and the AI. Freight is part of a material's price. Yields as licita: materials + equipment / yield + labor / yield. New ids, not licita's code ranges. 90010 is Sereno. Printing the analyses isn't needed; outputs are PDF.
- **Budget:** quantities read directly from the `.designer-proj`; sumi-designer is the master of which analyses each element type takes; items not from the design are made here; several coefficients at each level for particular reasons.
- **Gantt:** one task per item (a rubro shows an average when condensed); durations from the crews, set by the contractors; dependencies, milestones, critical path; the investment curve is needed.
- **Contracts:** contractor + items (or parts) + mode + conditions; certificates by measured progress, minus advance and retention, plus index adjustment; the AI drafts them from site reports, even voice input from the contractor's person; invoices, payments and the contractors' documents (insurance, ART, taxes); the contractors list is here and shared by all projects.
- **Interface:** Spanish and English only; the Spanish is kept up to date (said 2026-11-17).

## What it does (so far)
- **One project at a time:** `sumi.Project` (class `Project`). New and Open replace it, asking first if `RequiresSaving` is set (`actions.AskSave`).
- **Main window** (`fMain`), like the rest of the suite: the top bar (New, Open with the recent files, Save, Save as, Undo, Redo, Preferences, AI assistant, About), the tab strip `tabMain` and a status bar.
- **Tabs:** Project, Budget, Gantt, Pricing, Contracts, History. A tab is a form embedded in its page (`New FXxx(tabMain[TAB_XXX])` in `fMain.Run`), built in code with `Ui` helpers (no long `.form` files), with `ShowProject(p)` (a new or opened project) and `Reload()` (after any change: `sumi.Changed` -> `fMain.DataChanged` reloads the tab shown).
- **Every change goes through `Cmd`** (`.src/Document/Cmd.module`): `Cmd.Run(command, args)` returns `{ok, ...}` or `{error}`; args and results are JSON-like, so the AI calls the same commands as the screens. Each change is a `Change` in `Project.Changes` (who, when, `Who.Via`, model, command, args, targets with their before and after snapshots). Typing in one field coalesces into one change (`COALESCE_SECONDS`). `undo` restores the befores of the caller's last action (a whole group: an AI turn, an import) as a new entry; `redo` undoes that undo; an undo that would erase someone else's later change is refused. Targets: `project`, `book`, `rubros`, `charges`, `prices` (imports; no after kept), `resource:<id>`, `analysis:<id>`, `budget`, `schedule`. A new command: a `Case` in `Dispatch`, a line in `Help`, `Start` + `Touch(target)` before changing, validate before touching anything.
- **Ids** (`Ids.Make(prefix)`): everything referenced has a permanent id ("r-", "a-", "i-", "c-", "u-", "g-" + 12 base-32 characters, sortable by time); `Code` is what people see and can rename. Lines and items point by id.
- **Project tab (`FProject`):** the work, location, client, notes; schedule with holidays (`Project.EndDate`), the definitions (currency, general expenses, profit, taxes: `Project.PriceFactor`), the contract conditions and the professionals. Edits go through `project.set`.
- **Prices (`.src/Prices/`, `Project.Prices`, the Pricing tab `FPricing`):** `PriceBook` holds `Resource`s (material / labor / equipment; typed price, or calculated: labor from `Wage` + the book's `LaborCharge`s, equipment from its `MachineCalc` (`Machine`: depreciation + interest + repairs + fuel + lubricants, as licita2003's equ sheet) unless `PriceOverride`; loss %, freight `FreightPerKm × Distance / TruckLoad`, origin, updated, source), `Analysis` (code, rubro, unit, yields, `AnalysisLine`s of resources or linked sub-analyses), rubros and labor charges. `Parts` = [A materials, B equipment / EquipmentYield, C labor / LaborYield]; `PriceOf(r)` = (base + freight) × (1 + loss) × `UpdateCoef` (licita's coeficiente interno). Missing things cost 0 and are listed by `Problems`, never silently; loops are cut at `MAX_DEPTH`; `Flatten` merges sub-analyses (licita's "insertar análisis"). The tab: analyses list and sheet (lines by kind, totals, problems, pickers `FPick`), resources grid with the machine calculation, labor charges, rubros, the coefficient and freight, the import (report in `FReport`).
- **The licita2003 library:** `LibraryImport.ImportFolder` reads Tincho's CSVs (`~/.config/s64sketch/costs/licita2003` and `../added`), made from the user's `licita2003.xls` (its budget template `licita2003modelo.xxx` is lost). Codes stay as `Code`s; labor gets its wage and the mdo name (90010 Sereno), equipment its machine; typed prices that differ from the calculation are kept as overrides and reported; missing resources are made empty and reported. The xls's mdo sheet multiplies the charges by the wage twice (F3 = E3*D3 + D3); `PriceBook.LaborCost` uses wage + charges.
- **Budget (`.src/Budget/`, `Project.Budget`, the Budget tab `FBudget`):** `BudgetItem`s ordered by rubro and numbered "rubro.order" (`Renumber`): an analysis × a quantity, or a manual item with its `UnitCost`. Price = direct × `Factor` = `Project.PriceFactor` × the rubro's `Coef`s (`Budget.RubroCoefs`) × the item's (`Coef`: a reason and a %). `QtySource` "design" keeps `DesignQty`; a hand change is `Overridden` (orange). Reading quantities from the `.designer-proj` is next.
- **Gantt (`.src/Schedule/`, `Project.Schedule`, the Gantt tab `FGantt`):** a `GanttTask` per budget item (`Schedule.Sync` makes and drops them; the id is the item's): working `Days` (0 = milestone), `Crew`, `After` (finish to start) with `Lag`, `StartNotBefore`, `Done`. `Schedule.Compute` is the critical path on working days from the project's start (day 0 = the first working day; `DateOf` uses `Project.IsWorkDay`, holidays included); `SuggestDays` = quantity × labor hours a unit / (crew × hours a day); `Curve` = the price spent each month. The tab draws the bars in the grid's last column (`Tasks_Draw`); critical tasks red. Commands `schedule.get`, `task.set`.
- **Contracts (`.src/Contracts/`, `Project.Contracts`, the Contracts tab `FContracts`):** a `Contract` with a company contractor (by id), conditions from the Project tab (advance, retention, period, index name, base index and month), `ContractPart`s (a budget item, a quantity, the agreed unit price: an item can be split among contractors), `Certificate`s (advance / progress / retention; a progress one keeps the accumulated quantity measured of each part, starts where the last ended, and can't change once issued) and `Payment`s. `Contract.Numbers(cert)` = [work, adjustment = work × (index / base − 1), advance recovered = work × advance %, retention = (work + adjustment) × retention %, net]; the retention certificate gives back all the retentions. `Contracts.ItemMeasured` feeds the Gantt's progress. Commands contract.*, part.*, cert.*, payment.*.
- **Company data (`.src/Company/`, `~/.config/sumi-contract/company`):** shared by all projects, saved at once, with its own change log (`Company.Changes`; `Cmd.IsCompany` routes changes whose targets are `contractor:<id>` or `standard`; undo takes the newest of both logs by id). `Contractor`s with their `ContractorDoc`s (kind, number, expiry: red within 15 days; window `FContractors`), and `Company.Standard`, the standard price library: a new project starts with a copy; `standard.export` and `prices.fromStandard` merge by id.
- **Design link (`.src/Budget/DesignLink.module`, window `FDesign`):** sumi-designer writes `quantities` (rows with a language-independent `key` = group|item) and `analyses` (key → [{code, factor}]) into the `.designer-proj` on every save (branch `contract-quantities` of sumi-designer, file version 42). `design.sync` makes a budget item per row and analysis (`DesignRef` = "key#code", `QtySource` design); hand changes are kept and marked; rows that are gone get DesignQty 0. The designer's map is the master; `Budget.DesignMap` (`design.map`) fills the rows it doesn't map.
- **PDF reports (`.src/Reports/`):** `PdfDoc` writes PDF by hand (Helvetica base fonts, Windows-1252, Helvetica widths for alignment, footer "page n of m"); `Reports.Make(kind, file)`: budget, summary, analyses, gantt, certificate. The PDF menu in the top bar, the certificate's PDF button, the `report.pdf` command. The smoke test checks them with `pdfinfo`; `SMOKE_PDF_DIR=<dir>` keeps them, and `pdftoppm -png` turns them into images to look at.
- **History tab (`FHistory`):** the change log, filtered, with the before and after of each change; undo and redo.
- **AI assistant (`.src/Assistant/Assistant.module`, window `FAssistant`):** Claude (`Config.AIModel`, default `claude-opus-5-5`, effort `Config.AIEffort` set explicitly, server-side fallbacks with the `server-side-fallback-2026-07-01` beta) with one tool `sumi` {command, args} that runs `Cmd` as `Who.AI` with the model, plus `web_search_20260209` (Argentina) when `Config.AIWebSearch`. One request = one `Cmd` group (undone together). The conversation is append-only (thinking blocks go back unchanged); `pause_turn` is resent, `refusal` and errors drop the turn. HTTP through `HttpClient` (async), or files in `~/.config/sumi-contract/ai` with `Config.AIOffline`. The key: `Config.AIApiKey` or `ANTHROPIC_API_KEY`.

## Things worth knowing
- **Translation (keep it current):** the code is in English; every text people read is written `("...")` (or `Tr(x)` for values: then add the value to `.hidden/i18n/runtime.pot`). After changing texts: `.hidden/i18n/update.sh` (merges the new strings into `.lang/es.po` and compiles `es.mo`), add the Spanish of the new ones to the table in `.hidden/i18n/fill-es.py`, run `python3 -I .hidden/i18n/fill-es.py .lang/es.po` and `update.sh` again until it says 0 strings to translate. Argentine construction words: rubro, análisis de precios, insumo, certificado, anticipo, fondo de reparo, redeterminación, mano de obra, obrador, comitente. A text matched inside another (`("analyses use")`, `("changed after that")`, `("Undo: ")`) must be translated with the same words as the long one. The smoke test checks that Spanish loads, then runs in English (`System.Language`).
- **Building:** `gbc3 -a -w .` in the project folder (`-g` adds line numbers to runtime errors). Don't pipe it through `tail` before `&& gbx3`: the pipe hides a failed compile and the old build runs.
- **Smoke test:** `gbc3 -a . && gbx3 . -- --smoke-test`; exit code = failures (271 checks now). It uses a temporary folder for config and files, and the real licita2003 CSVs when the computer has them (`SMOKE_VERBOSE=1` prints the import report). It covers the config, the file, the schedule, CSV, ids, the price model, the import, the commands with the log, undo and redo, the assistant's loop with canned API replies, the budget and the Gantt (critical path, lags, loops, dates on working days, the investment curve). Add a check for every new feature.
- **Window test:** `gbx3 . -- --gui-test` opens the window, imports the library, goes through every tab and page and the assistant's window, and quits (0 = OK, 1 at the first error, which is in `~/.config/sumi-contract/logs`; run it with `timeout` anyway). `SMOKE_TRACE=1` prints each check of the smoke test as it runs. `GUI_SHOTS=<dir>` saves screenshots where the desktop allows it (not on this Wayland desktop).
- **`IIf` evaluates both branches:** `IIf(b, b.Code, "")` fails when `b` is Null and `IIf(x, a / x, 0)` divides by zero. Use `If`.
- **Form members:** a form's own `Refresh`, `Text`... can't be redefined (hence `Reload`). A property can hide a class of the same name (`Resource.MachineCalc`, not `Machine`; `Change.Params`, not `Args`; `Assistant.Failure`, not `Error`).
- **Names are not case-sensitive:** a constant `ROW` and a routine `Row` clash. Grid cells have no `ToolTip`.
- **Editing Cmd.Help with scripts:** a line ending `= "` followed by the replacement's own `"` gives `""{...` (it happened three times): check the line after.
- **sumi-designer shares many files with sumi-e through symlinks** (`AssetMesh.class`...): a change in sumi-e can break the designer's build (it did on 2026-11-17: `DxfMesh`).
- **Built-in class names:** `Task` is Gambas's (background tasks, not creatable): hence `GanttTask`. Check a new class name isn't taken.
- **After an unhandled error** the program waits instead of ending (the network components keep it alive): `main.Application_Error` quits with 1 in the test modes (`--smoke-test`, `--gui-test`).
- **Tab pages** (`TabPanel[i]`) have no `Arrangement`: set it on the TabPanel, or put a box in the page.
- **Arrays:** only `String[]` has `Join`; use `Utils.JoinNumbers` for `Integer[]` / `Float[]`. `New` can't be used inside an expression (an argument). `Match` needs gb.pcre: use `Utils.IsDigits` and the like.
- **JSON** is in `gb.util.web` (`JSON.Encode` takes only the value). `JSON.Decode(s, True)` keeps nulls (the assistant needs it). Collections drop keys set to `""`/Null, hence `Cmd.ABSENT` for "didn't exist" and `Config.$aDefaultNames`.
- **The compiler doesn't check members:** `Config.Typo` compiles and fails only when run. After renaming, grep for callers (`grep -a`).
- **Embedded forms:** a tab form gets `Form_Open` only when first shown: set it up in `_new()`. Event groups: attach in code (`Object.Attach`, or `New X(parent) As "Group"`).
- **Reserved words:** `Use` can't be a variable name (`Project.Usage`, key `"use"`).
- **Objects held across commands go stale:** `undo` replaces the restored objects (`Restore` makes new ones), so always reach them through `sumi.Project` again.
